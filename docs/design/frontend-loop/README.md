# 前端逐页反馈循环

状态：用户已选择 B「纸感阅读室」，主要页面已实施。2026-09-14 继续修复辅助字号、搜索键盘导航和图谱标签边界。最新证据见 `.scratch/frontend-loop/followup-2026-09-14.md`。

## 本轮范围

依次处理文档库 → 时间轴 → 知识图谱 → 数据看板 → 待整理 → 标签词表 → 问答 → LLM 设置 → 导出 Vault → 新解析 → 修复报告。之后补文档编辑器与 PDF 详情（需要专用测试数据）。

这是有终止条件的开发反馈循环，不是后台定时任务。方向确定后，每页执行以下步骤，无需逐页再次确认：

1. 读取该页的 HTML、样式、视图模块及相关测试，记录真实任务与入口。
2. 截取修改前的 1440×900 和 390×900 界面。覆盖空状态、有内容状态、加载失败状态；无法覆盖时明确标记未测。
3. 评审信息层级、排印、操作可发现性、键盘操作、焦点、溢出和文案。按严重程度排序，优先修阻断任务的问题。
4. 在既有结构中实施最小完整修改，不更改 API、存储或自动保存契约。涉及契约时补充有意义的测试。
5. 运行相关模块测试，重新截图并肉眼检查；执行关键交互，记录结果。
6. 最多三轮修正；达到验收条件就进入下一页。若三轮仍有问题，写出具体证据和剩余问题，继续独立页面，不做无止境重试。
7. 全部页面完成后做一次跨页回归。仅当出现新失败才重复检查。不得把没有测试结果当成通过，也不等待不存在的 CI。

## 验收条件

- 页面主操作明确，导航选中状态和实际路由一致。
- 桌面无意外裁切；窄窗口可到达所有关键操作，必要滚动有明确容器。
- 正文至少 14px、辅助标签至少 12px，正文对比度至少 4.5:1。
- Tab 可以到达关键控件且焦点可见；空状态和错误状态说明下一步。
- 本地关键交互与相关测试通过，无新增 pageerror。
- 每页具备前后截图、修改理由和剩余限制。图谱还需检查节点可读性；编辑器还需检查保存状态和三栏滚动；问答还需检查引用与会话恢复。

## 可重复巡检

启动应用时指定独立测试存储目录：

```sh
GRAPH2NOTE_STORAGE="$PWD/.scratch/frontend-loop/storage" .venv/bin/python -m uvicorn graph2note.webapp:create_app --factory --host 127.0.0.1 --port 8794
```

在另一个终端运行（需可用的 Playwright 与 Chrome）：

```sh
node scripts/frontend_audit.mjs http://127.0.0.1:8794 .scratch/frontend-loop/evidence
```

若 Playwright 不在项目模块路径，可用 `PLAYWRIGHT_MODULE` 指向其 `index.mjs`；`CHROME_BIN` 可覆盖 Chrome 路径。脚本使用独立浏览器上下文，只访问页面，不提交上传、模型调用、保存、删除或导出。发现 JS 异常或横向溢出时退出码为 1，截图和 audit.json 仍保留。

自动巡检只证明路由渲染和几何检查，不证明业务成功、可访问性全面合格或设计优秀。应用巡检覆盖 390 / 768 / 1440px，可对空库和独立测试库分别执行。编辑器保存、PDF 上传和问答的浏览器交互使用拦截响应，不发起真实模型调用。通过可选参数 `--prototypes` 才执行原型检查，该检查依赖 `.scratch/frontend-loop/design-demos/` 中的本轮三个初稿；它们是视觉比较材料，不是应用功能替代品。
