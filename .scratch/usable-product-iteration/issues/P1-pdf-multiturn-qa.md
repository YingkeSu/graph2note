# P1：PDF 多轮问答（会话态与上下文）

Status: merged
Labels: track-pdf-qa

## What to build

覆盖 usable-product-iteration 草案 §2.4。把 `/api/pdf/ask` 从单轮升级为多轮：同一会话内可追问，答案仍带独立可验证的页级引用。

- **会话模型**：`session_id` 显式传入；服务端保留会话态（内存 + 可选落盘到 storage，进程重启后可恢复——落盘为应做项，容量上限显式）。无 `session_id` 视为新会话（向后兼容现有单轮调用）。
- **上下文策略**：携带最近 5 轮问答（问题 + 答案 + 引用页码）；检索每轮独立执行（当前问题决定检索词，历史只进 prompt 上下文，不参与检索加权——首版简单可解释）。上下文截断规则显式。
- **引用纪律不放松**：每轮答案的页级引用来自**当轮**检索命中；无证据时明确说明，不允许引用历史轮的页码冒充本轮证据。回答里历史引用需标注"前文提到"。
- **scope 沿用**：会话绑定检索 scope（单 PDF 或列表，为 P3 跨文档预留参数形态）；会话内切换 scope 即新话题，实现为显式新会话而非隐式切换。
- **预算**：每轮调用沿用现有超时与 token 上限；会话计数与 token 消费进遥测（telemetry 既有通道）。

## Acceptance criteria

- [ ] 同一 `session_id` 连续 3 轮追问：第 2、3 轮 prompt 含前轮问答（录制请求体断言），检索词只来自当轮问题。
- [ ] 每轮引用页码均来自当轮检索命中（构造 fixture：历史轮命中页 A、当轮命中页 B，断言答案引用 B 而非 A）。
- [ ] 无 `session_id` 调用行为与现状一致（向后兼容契约测试）。
- [ ] 超过 5 轮后最老轮次被截断（断言 prompt 长度规则）；落盘会话重启后可续问。
- [ ] stub/录制 LLM 输出的离线测试全链路（请求组装 → schema 校验 → 响应）可重复，CI 无真实调用；真实冒烟一次记 handoff（预算 ≤3 次调用）。
- [ ] 会话 token 消费进遥测记录。
