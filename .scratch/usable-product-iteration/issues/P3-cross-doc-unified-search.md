# P3：跨文档问答与统一搜索（⌘K）

Status: ready-for-agent
Labels: track-pdf-qa

## What to build

覆盖 usable-product-iteration 草案 §2.4。两件事：问答 scope 突破单 PDF；文档（手稿解析产物）内容进统一检索，与 PDF 内容共用一个搜索入口。

- **跨文档问答**：scope 支持多 PDF 选择与「全部」；检索在各 PDF 间合并排序（沿用关键词索引，按文档/页聚合命中，引用标注 PDF + 页码）；无命中的 PDF 不进上下文。首版不做向量检索（草案既定；embedding 通道为开放问题，不在本 issue）。
- **统一索引**：文档 Markdown 进检索索引（块或段级，实现自定；与 `pdfsearch` 共用引擎与 API 形态——建议抽出共同检索层而非复制代码）。文档增删改（含 R1 重跑产生新版本）后索引增量更新，口径沿 baseline issue 10 的索引一致性要求。
- **⌘K / 顶栏搜索框**（U1 预留的占位落地）：唤起统一搜索面板，输入即搜（标题 + 文档内容 + PDF 内容），结果分组展示（文档 / PDF 页），文档结果点击进编辑器，PDF 结果点击跳原页；⌘K 全局唤起（输入框聚焦时除外）、Esc 关闭。
- **问答联动**：搜索面板提供「就这些结果提问」入口，携带当前查询词进入问答视图（消费 P2）预填首问——把"搜到 → 问深"串起来。

## Acceptance criteria

- [ ] 问答 scope=多 PDF 时，检索命中文档合并排序，引用含 PDF 名 + 页码；无证据回答与引用纪律沿 P1 口径（stub 测试断言）。
- [ ] 文档 Markdown 入索引：新建/编辑/删除文档（含 R1 修复产生的新版本）后索引一致（复用 baseline issue 10 的索引一致性测试口径，扩展到文档源）。
- [ ] ⌘K 全局唤起搜索面板，Esc 关闭；结果分组（文档/PDF 页），点击分别进编辑器/跳原页（DOM 断言）。
- [ ] 「就这些结果提问」把查询词带入问答视图预填（跨视图状态传递测试）。
- [ ] 索引构建/更新对 43 篇库 + 多 PDF 的耗时记录在 handoff（无硬性指标，但需可感知不卡顿）。
- [ ] 离线契约测试全绿；CI 无真实模型调用。
