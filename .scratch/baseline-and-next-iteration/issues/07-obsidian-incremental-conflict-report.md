# 展示 Obsidian 增量变化与冲突结果

Status: ready-for-agent

来源：[已确认拆分草案](../ISSUE-DRAFT.md)；[现状与需求检查](../ASSESSMENT.md)。

覆盖需求：导出可重复使用，用户知道哪些内容更新、哪些手工修改被保留。

## What to build

在 Web 导出流程中展示新增、更新、删除、无变化和冲突明细。冲突项给出保留文件位置与受管输出位置，让用户能够核对两份内容；不实现自动语义合并。

## Acceptance criteria

- [ ] 首次导出、无变化重跑、修改内容/元数据、删除文档均返回与落盘一致的分类明细。
- [ ] 无变化重跑不改写文件；用户手工编辑或改名的文件仍被保留，结果中能定位这些文件。
- [ ] 界面明确说明“保留用户备份并生成系统版本”，不将冲突保护描述为已自动合并。
- [ ] 导出失败或部分完成能区别显示；不把不同任务的报告混用，也不让重试掩盖已发生的冲突。
- [ ] 离线端到端场景覆盖用户编辑、改名、重跑、来源/附件引用与元数据更新。
