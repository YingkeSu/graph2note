# 建立原稿与产出对照视觉验收命令

Status: merged

来源：[已确认拆分草案](../ISSUE-DRAFT.md)；[现状与需求检查](../ASSESSMENT.md)。

覆盖需求：开发过程中检查 Markdown、公式、表格和重建图的准确性。

## What to build

沿用 UI 验收的调用、预算与证据机制，增加独立的内容验收模式：对照原稿图片、候选 Markdown 与渲染产物，报告漏字、增写、公式、表格与图形关系差异。与 UI 验收分别维护提示词、样例及结果口径。

## Acceptance criteria

- [ ] 同一套输入样例可通过命令完成原稿/候选产物加载、视觉检查和报告生成，不改变产品解析结果或用户文件。
- [ ] 每项差异包含源证据、候选证据、页/块/区域定位及建议；看不清、缺少附件、无法判定时明确报告，不编造结论。
- [ ] 正确/错误控制样例覆盖文字、公式指数、表格单元格和箭头方向；另有真实手稿与重建图样例，记录误报和漏报。
- [ ] 图片及候选内容只作为待检查数据，不被当作运行指令；调用预算、错误语义和离线重放沿用 04。
- [ ] 固定输入与提示词版本可复查结果；开发文档明确此命令是质量辅助，不替代 IR、渲染确定性和附件完整性检查。
