# 科研周报模板与增量整理 PRD

Status: ready-for-agent

> 范围：需求与规划；子 issue 拆分及测试边界待用户确认，本文不授权启动实现。

## Problem Statement

现有周报是文档库四节小结，难以直接作为个人科研汇报。用户已在 MacBook 调出满意的 20260907 周报，包含研究路线、项目进展、贴着正文的手写批注和原稿附录。模板形成过程暴露了追加覆盖、虚构实验、识别内容不分段、长批注迫使正文空白等问题；当前应用另有 PDF 渲染疑似故障，需要独立定位。

## Solution

提供可持续编辑、逐段补充、有来源证据的科研周报模板；以语义内容与关联侧注驱动网页阅读、Markdown 归档和 PDF 分享。延续现有日期范围、预算、缓存、历史和来源能力，新增模块配置与修订。采用 [模板设计](TEMPLATE.md)，依据 [参考记录](REFERENCES.md)。

## User Stories

1. As a 科研周报作者, I want 选择本周、上周或自定义范围，以便准确汇报对应周期。
2. As a 科研周报作者, I want 填写汇报人和日期，以便直接分享报告。
3. As a 科研周报作者, I want 选择科研周报模板，同时打开旧版小结，以便连续使用历史资料。
4. As a 科研周报作者, I want 看到研究主线、副线与成果概览，以便快速说明这一周的重点。
5. As a 科研周报作者, I want 按主题整理进展及其证据，以便汇报可核实的工作。
6. As a 科研周报作者, I want 区分已知、推论、猜想、待验证及计划，以便避免虚构成果。
7. As a 科研周报作者, I want 加入本机以外工作的文字补充，以便完整记录本周工作。
8. As a 科研周报作者, I want 逐段追加并立即预览，以便及时调整表达。
9. As a 科研周报作者, I want 锁定需要原文保留的段落，以便生成时不被改写。
10. As a 科研周报作者, I want 查看新旧修订并重新打开旧版，以便避免修改丢失。
11. As a 科研周报作者, I want 合并重复笔记并保留所有来源，以便减少冗余又可追溯。
12. As a 科研周报作者, I want 按需启用、关闭和排序专题章节，以便不被占位实验章节误导。
13. As a 科研周报作者, I want 保留空的问题与求助标题，以便保持汇报习惯。
14. As a 科研周报作者, I want 维护下周待办，以便将计划与完成事项分开。
15. As a 科研周报作者, I want 在对应正文旁写 tips 与碎碎念，以便批注有上下文。
16. As a 科研周报作者, I want 阅读长批注时正文不产生异常空白，以便保持阅读连贯。
17. As a 科研周报作者, I want 展示已有整理图、表格、公式和代码，以便准确表达研究内容。
18. As a 科研周报作者, I want 从正文跳到原图附录与具体来源页，以便核对整理结果。
19. As a 科研周报作者, I want 在窄屏阅读顺序正确的报告，以便随时检查内容。
20. As a 科研周报作者, I want 导出携带图片的 Markdown 及清晰的 PDF，以便归档分享。
21. As a 科研周报作者, I want 重新打开历史报告仍看到当时的内容和版式版本，以便稳定存档。
22. As a 科研周报作者, I want 了解材料截断、来源缺失与生成失败，以便采取恢复操作。
23. As a 科研周报作者, I want 复用未变材料的结果，以便避免重复模型费用。
24. As a 科研周报作者, I want 明确 PDF 故障发生在哪个入口并得到可复现诊断，以便针对性修复。

## Implementation Decisions

- 保留原小结兼容路径；科研模板具有稳定 template_id/version，报告 schema 与生成提示独立版本化。历史快照不随模板升级重排。
- 扩展已有周报生成、持久化与阅读能力，报告内容由稳定章节/段落 ID、模块配置、批注锚点、来源及版本、资产引用、汇报信息组成；Markdown/PDF 均消费同一快照，避免平行存储各自漂移。
- 继续复用现有周报创建/列表/详情边界，新增修订保存与导出能力。CLI 的既有范围和 Markdown 使用方式保留；不要求 CLI 提供交互编辑器。
- 生成使用现有注入式 text planner；事实来自材料或显式用户补充，未知结果不得补全。模块关闭不触发对应模型生成。统计确定性计算，不让模型猜测数值。
- 缓存键覆盖日期范围、材料版本/内容、模板版本、模块选择顺序、补充材料及相关生成约束；纯布局变更不应无谓调用模型。强制重生成创建新修订，不覆盖手动确认/锁定内容。
- 追加有明确目标章节，重复来源不丢引用；保存采用修订冲突检测，过期页面不得静默覆盖新内容。来源删除或资产缺失保留快照文本并显示状态。
- 侧注绑定稳定段落；使用独立的侧注排布与续注规则，移动端按语义顺序线性化。屏幕与打印分别验证，不能仅凭 DOM 测试判定分页正确。
- 原图附录与已有整理图并存，保留来源文档/页/版本。图表、脚注、口径由原材料决定，不新增外部检索或自动价格更新。
- PDF 输出采用共享 HTML/CSS 报告布局与可打包的打印渲染能力；引擎选型以实际 macOS 环境验证为准，不预先强绑 TeX。字体及资产可离线加载，失败须明确报告而非提供空白成功文件。
- 新增 PDF 诊断是有界研究任务；先区分论文原件、逐页页图、结构化预览、桌面 WebView 与导出入口，关联既有预览修复单，不能直接重写全链路。

## Testing Decisions

- 主要测试边界：现有应用 HTTP 创建/保存/读取报告 → 浏览器阅读 → 下载产物；注入离线 planner 与固定材料，验证用户可见结果、重启持久化及零额外模型调用，不测试内部拆分方式。
- 复用已有周报 API/CLI 契约、结构/预算测试和 Node DOM 契约；增加真实浏览器及 macOS 应用的页面/打印验收。旧版兼容也走读取及导出行为。
- 重点样本：用户补充两次仍保留首段、重复笔记合并来源、锁定文字逐字保留、无实验材料不生成实验成果、修订冲突、模板变更不命中旧缓存、空材料不调用模型、资产缺失恢复。
- 版式样本：390/768/1440 宽度、9 页级报告、长侧注、跨页图表、长 URL、中文/英文/编号/emoji。检查内容完整、无重叠裁切、批注锚点正确、正文不因左栏填充而出现大段空白。
- PDF 同时做文本/页数/链接检查与逐页渲染人工检查；文件存在或 HTTP 200 不代表视觉正确。
- 待用户确认：以上以应用端到端为主、离线模型替身加真实 PDF 视觉验收的边界是否符合预期。无需 live LLM 才能完成常规验收。

## Out of Scope

不在本次规划阶段实现代码；不建设 LaTeX 编辑器、全套模板市场、协作系统、定时发送、外部实时价格研究或全新图形生成器；不重构论文解析与问答全栈；不将参考周报中的研究观点和数值固化为模板事实。

## Further Notes

参考起始周为 2026-09-07 至 09-13，文件夹名 260907；根目录旧 PDF 不作为最新排版依据。新日期范围沿用项目有效时间规则。当前 PDF 故障尚未本次复现；诊断子单与已有论文预览修复工作关联，不混淆两者。见 drafts 下完整子单草稿，确认后按依赖顺序发布到 issues。
